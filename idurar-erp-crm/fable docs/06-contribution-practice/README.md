# 06 — Contribution Practice

Realistic work, sized for growth. Every ticket answers: why is it useful, why is the blast radius small, what pattern does it follow, how is it tested, and what would make a maintainer reject it. No drive-by refactors.

2. [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) — 10 cross-layer tickets requiring design notes.
3. [03-senior-build-projects.md](03-senior-build-projects.md) — 6 projects (days to weeks) a maintainer might actually accept.
4. [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) — senior katas with self-grading.

Every ticket and project has an **Interview story potential** line — the STAR story completing it would produce, cross-linked to [08-interview-prep/06-behavioral-star-stories.md](../08-interview-prep/06-behavioral-star-stories.md).

**Realism note:** because this copy has no tests, "how it's tested" often means manual verification steps or "add the first test for this path." Several tickets fix the confirmed defects of this copy (broken routes, crashing setup). Do those first — they're the highest-value, lowest-risk contributions available.
